# DMSH Victorina — музыкальный тренажёр для ДМШ

> **Статус:** проектирование / разработка первой версии. Описанные ниже функции — требования к проекту, а не утверждение о том, что они уже реализованы.

**DMSH Victorina** — кроссплатформенное веб-приложение для изучения и узнавания музыкальных произведений на слух. Предназначено для учеников детских музыкальных школ, прежде всего для предметов «Слушание музыки» и «Музыкальная литература».

**Главная цель — обучение, а не оценка.** Ребёнок должен иметь возможность самостоятельно познакомиться с музыкой, запомнить композитора, название произведения и его часть, многократно прослушать фрагменты и потренироваться без помощи родителей.

Репозиторий: https://github.com/sinitsinmike/DMSH_victorina

## Основной сценарий ученика

1. На главной странице выбрать одну из опубликованных тематических подборок.
2. На странице **«Изучение»** слушать записи, одновременно видя композитора, название произведения и часть/номер (если есть).
3. Нажать **«Викторина»**, чтобы открыть страницу сопоставления аудиофрагментов с карточками ответов.
4. Перетаскивать карточки мышью или касанием; на телефоне предусмотреть альтернативу перетаскиванию — выбор касаниями.
5. В режиме тренировки получать немедленную обратную связь. В режиме теста проверять знания по выбранному правилу.

### Страница «Изучение» (`study.html`)

- Карточка произведения содержит композитора, название, необязательную часть/номер и кнопку воспроизведения.
- Повторное прослушивание не ограничено.
- Одновременно звучит не более одного MP3.
- Основная кнопка перехода — **«Викторина»**.

### Страница «Викторина» (`quiz.html`)

- Для *N* фрагментов формируются ровно *N* карточек ответов. Все карточки являются правильными ответами, но каждая соответствует своему фрагменту.
- Каждая карточка показывает **композитора + произведение + необязательную часть/номер**.
- Порядок фрагментов и карточек перемешивается независимо.
- На экране есть аудиофрагменты с областями ответа и общий набор карточек.
- Правильное соответствие подсвечивается зелёным; ошибочное — красным в режиме немедленной проверки.
- **Ключевое правило:** неверно выбранная карточка не должна становиться недоступной для другого фрагмента, которому она действительно соответствует. Ошибка в одном задании не должна автоматически делать невозможным правильный ответ в другом.
- Для одного фрагмента отображается один текущий ответ; его можно заменить. При необходимости история попыток сохраняется отдельно.

**Режимы:**

1. **Тренировка** (основной): немедленная проверка, неограниченные попытки, ошибочная карточка возвращается в доступный набор, верная закрепляется.
2. **Тест** (переключатель на странице викторины): прототип должен позволять сравнить два варианта — немедленную подсветку и проверку только после завершения. Окончательное поведение выбирается после практического тестирования. В обоих вариантах ошибочный выбор не должен лишать ученика возможности использовать карточку для другого вопроса.

В дальнейшем: статистика сложных произведений, повторение ошибок, локальный прогресс и результаты тестов.

## Конструктор преподавателя (`teacher.html`)

**Преподавателю не нужно знать HTML, JavaScript или JSON.** Конструктор представляет собой обычную веб-форму.

Возможности первой версии:

- Создать новую викторину: название, класс, описание.
- Добавить любое число произведений.
- Для каждого произведения указать MP3, композитора, название и необязательную часть/номер.
- Прослушать выбранный MP3 перед экспортом.
- Изменить порядок, удалить или добавить произведения.
- **Экспорт JSON** — скачать готовый файл без ручного редактирования.
- **Импорт JSON** — открыть ранее созданную викторину для исправления или дополнения.
- Проверка заполнения обязательных полей и ссылок на аудио.
- Автоматическое локальное сохранение черновика, чтобы введённые данные не терялись при случайном закрытии страницы.

В нижней части страницы должна быть **простая пошаговая инструкция для преподавателя**: куда загрузить MP3, куда положить экспортированный JSON и как проверить публикацию. Не использовать терминологию, требующую навыков программирования.

## Хранение данных

**Один сайт обслуживает много независимых викторин.** Удалять MP3 при создании следующей викторины не нужно.

- `MP3/` — общая библиотека звуковых файлов; исходные имена сохраняются. Один файл может использоваться в нескольких викторинах.
- `quizzes/` — отдельный JSON-файл на каждую викторину.
- `quizzes/index.json` — каталог опубликованных викторин, который планируется обновлять автоматически через GitHub Actions.
- Страницы сайта универсальны и не редактируются для каждого нового набора.

> **Важно:** в репозитории уже существует каталог `MP3/` с заглавными буквами. На GitHub Pages регистр пути имеет значение: используем именно `MP3/`, а не `mp3/`, если не принято отдельное решение переименовать папку.

### Пример формата викторины (предварительная схема v1)

```json
{
  "schemaVersion": 1,
  "id": "nutcracker_3class",
  "title": "Балет «Щелкунчик»",
  "class": "3",
  "description": "Узнавание музыкальных номеров",
  "tracks": [
    {
      "id": "track_001",
      "composer": "П. И. Чайковский",
      "work": "Балет «Щелкунчик»",
      "part": "Марш",
      "audio": "MP3/Tchaikovsky - March.mp3"
    },
    {
      "id": "track_002",
      "composer": "П. И. Чайковский",
      "work": "Балет «Щелкунчик»",
      "part": "Танец феи Драже",
      "audio": "MP3/Tchaikovsky - Sugar Plum Fairy.mp3"
    }
  ]
}
```

Это **пример структуры**, а не готовая викторина: названия MP3 иллюстративны и должны соответствовать реально загруженным файлам. Пути к аудио интерпретируются относительно корня сайта. При разработке необходимо валидировать JSON и корректно обрабатывать пробелы и кириллицу в именах файлов.

## Как преподавателю опубликовать новую викторину

1. Откройте страницу **«Конструктор преподавателя»**.
2. Заполните название, класс и сведения о произведениях; выберите MP3.
3. Нажмите **«Экспорт JSON»** — файл скачается на компьютер.
4. В репозитории GitHub откройте папку **`MP3/`** и загрузите туда новые аудиофайлы через **Add file → Upload files → Commit changes**. Уже существующие файлы загружать повторно не нужно.
5. Откройте папку **`quizzes/`** и таким же способом загрузите полученный **`.json`**.
6. Дождитесь обновления GitHub Pages, откройте каталог викторин и проверьте воспроизведение.

**Обратите внимание:** выбор локального MP3 в конструкторе не загружает его автоматически на GitHub. JSON содержит ссылку на файл, который нужно разместить отдельно. До реализации автоматического каталога `quizzes/index.json` новая викторина не сможет появляться в списке без дополнительного механизма индексации.

## Технические принципы

- Статический веб-сайт на GitHub Pages; без обязательного собственного сервера.
- HTML, CSS и JavaScript; в перспективе PWA и офлайн-кэширование выбранных подборок.
- Адаптивный интерфейс для компьютеров, планшетов и смартфонов.
- Особое внимание совместимости со школьными Intel iMac на **macOS High Sierra** и доступными на них браузерами.
- Для перемещения карточек предусмотреть работу с мышью и сенсорным экраном; не полагаться только на нативный HTML Drag and Drop для мобильных устройств.
- Один активный аудиоплеер за раз.
- Содержимое викторин отделено от кода; новые подборки не требуют изменения HTML/JS.
- Локальные черновики и прогресс могут храниться в браузере; синхронизация результатов — отдельный будущий этап.
