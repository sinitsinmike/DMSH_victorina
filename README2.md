# DMSH Victorina — музыкальный тренажёр для ДМШ

**Репозиторий:** https://github.com/sinitsinmike/DMSH_victorina  
**Статус:** подробное техническое задание и целевая архитектура. Описанные функции **не следует считать уже реализованными**.  
**Язык интерфейса:** русский.  
**Основная аудитория:** ученики детской музыкальной школы и преподаватели предметов «Слушание музыки» и «Музыкальная литература».

## 1. Зачем нужен проект

Цель — **научить ребёнка узнавать изучаемые музыкальные произведения на слух**, а не просто выставлять оценку. Ученик дома часто не может самостоятельно сыграть или найти нужный фрагмент оперы, балета или симфонии; родители тоже не обязаны знать репертуар. Приложение должно давать ребёнку готовые записи с названиями, возможность многократно слушать и сравнивать, а затем самостоятельно сопоставлять музыку с названиями.

**Главный сценарий:** выбрать тематическую подборку → изучить произведения с подписями → нажать «Викторина» → распределять карточки по звучащим фрагментам → при необходимости включить «Тест». Режим обучения важнее контрольного режима.

### Основные принципы

1. **Один универсальный сайт, много викторин.** Для новой подборки не изменяются HTML и JavaScript.
2. **Одна общая папка `MP3/`.** Файлы не удаляются при создании новых викторин; один MP3 может использоваться в нескольких наборах.
3. **Один JSON на одну подборку.** Учитель создаёт его через форму, не пишет JSON вручную.
4. **Все варианты ответа берутся из самой подборки.** Если в ней 10 произведений, на экране 10 аудиофрагментов и 10 карточек ответов; «ложных» ответов извне нет.
5. **Ответ — единая карточка:** композитор + название произведения + необязательная часть/номер.
6. **Ошибка в одном вопросе не должна лишать ученика правильной карточки для другого вопроса.** Доступность ответа и его текущее размещение — разные понятия.
7. **Компьютер и телефон равноправны.** Перетаскивание мышью/пальцем и доступная альтернатива касаниями.
8. **Преподаватель не программист.** Интерфейс конструктора, проверки и инструкция по публикации — на понятном русском языке.

## 2. Архитектура и структура файлов

```text
DMSH_victorina/
├── README.md
├── index.html                   # каталог всех опубликованных подборок
├── study.html                   # изучение выбранной подборки
├── quiz.html                    # карточки, тренировка и тест
├── teacher.html                 # визуальный конструктор и экспорт JSON
├── css/
│   └── style.css
├── js/
│   ├── app.js                   # общая загрузка, маршрутизация, ошибки
│   ├── data.js                  # проверка схемы JSON, безопасные пути
│   ├── audio.js                 # один активный проигрыватель
│   ├── study.js                 # экран изучения
│   ├── quiz.js                  # логика распределения и проверки
│   └── teacher.js               # редактор, импорт, экспорт, черновики
├── MP3/                         # общая библиотека MP3, имена сохраняются
│   ├── ...
├── quizzes/
│   ├── index.json               # автоматически сформированный каталог
│   ├── nutcracker_3class.json   # пример независимой подборки
│   └── ...
├── data/
│   └── mp3-index.json           # автоматически сформированный список MP3
└── .github/
    └── workflows/
        └── update-index.yml    # генерация индексов после загрузки файлов
```

**Важно:** в репозитории используется папка **`MP3/` с заглавными буквами**. На GitHub Pages `MP3/` и `mp3/` — разные пути. Не переименовывать её незаметно в коде.

### Назначение частей

- **GitHub Pages** раздаёт HTML, CSS, JS, JSON и MP3. Собственный сервер для первой версии не нужен.
- **`quizzes/*.json`** — исходные данные конкретных подборок; в них нет копий аудио.
- **`quizzes/index.json`** — каталог, из которого главная страница узнаёт о новых подборках. Статический сайт **не умеет сам перечислять содержимое папки**.
- **`data/mp3-index.json`** — список опубликованных MP3 для выпадающего выбора в конструкторе и проверки существования.
- **GitHub Actions** при изменениях в `quizzes/` или `MP3/` пересобирает индексы. Нужна защита от бесконечного запуска workflow при записи сгенерированных файлов.
- **Браузер** читает данные, проигрывает аудио и обрабатывает ответы. Никаких секретных токенов GitHub в клиентском JavaScript.

### Адреса и навигация

Для GitHub Pages проекта базовый адрес предполагается таким:

`https://sinitsinmike.github.io/DMSH_victorina/`

- `index.html` — выбор подборки.
- `study.html?quiz=nutcracker_3class` — изучение выбранной подборки.
- `quiz.html?quiz=nutcracker_3class` — задания той же подборки.
- `teacher.html` — редактор преподавателя.

Значение `quiz` — **идентификатор**, а не произвольный путь к файлу. Приложение находит его в каталоге, не позволяет подставлять `../` или внешние адреса. Все ссылки на MP3 вычисляются **от корня сайта**, а не от страницы или папки JSON. Имена с пробелами и кириллицей кодируются при формировании URL, но исходные имена файлов не меняются.

## 3. Главная страница (`index.html`)

Заголовок «Музыкальная викторина ДМШ». Ниже — список опубликованных подборок. Для каждой показывать название, класс, описание (если есть), количество произведений и кнопку **«Изучить»**. В дальнейшем можно добавить поиск и фильтр по классам.

**Поведение:**

1. Загрузить `quizzes/index.json`.
2. Для каждой опубликованной записи показать карточку.
3. По кнопке «Изучить» перейти на `study.html?quiz=<id>`.
4. Если каталог не загрузился, показать понятное сообщение и кнопку «Повторить», а не пустой экран.
5. Отдельная ссылка «Преподавателю — создать викторину» ведёт на `teacher.html`.

Добавление нового JSON в `quizzes/` и обновление индекса автоматически добавляет карточку в каталог. **Никакого ручного изменения главной страницы.**

## 4. Страница изучения (`study.html`)

Это **основной учебный этап**, а не проверка знаний.

Для каждого произведения отображается карточка:

- Композитор.
- Название произведения.
- Часть, действие, сцена или номер — **только если заполнено**.
- Кнопка ▶ / пауза, полоса прогресса и длительность записи.

Ученик может слушать любое произведение сколько угодно раз, в любом порядке, одновременно читая название. При запуске нового фрагмента предыдущий останавливается. Для мобильных браузеров звук запускается **по действию пользователя**, без принудительного автозапуска.

Кнопка **«Викторина»** открывает `quiz.html` с тем же идентификатором подборки. Кнопка «К списку викторин» возвращает на главную. При невозможности загрузить аудио показывать, **какой файл не найден**, без падения всей страницы.

## 5. Страница викторины (`quiz.html`)

### 5.1. Макет

**Верхняя панель:** название подборки, ссылка «К изучению», индикатор заполнения («Распределено 6 из 10»), переключатель **«Тренировка / Тест»**.

**Основная область:**

- На широком экране слева — пронумерованные фрагменты с ▶ и областью для ответа; справа — общий набор карточек произведений.
- На узком экране — вертикальный адаптивный интерфейс. Должен работать без точного перетаскивания: нажать карточку → нажать целевой фрагмент (или наоборот).
- На каждой карточке: композитор, произведение, часть/номер при наличии.
- Аудиофрагменты и карточки **перемешиваются независимо** при начале нового прохождения. Перемешивание не меняет связи с правильными ответами.
- Одновременно воспроизводится не более одного MP3.

### 5.2. Идентификаторы, а не позиции

Каждый фрагмент имеет стабильный `track.id`. Правильность определяется **сравнением ID выбранной карточки с ID соответствующего фрагмента**, а не текстом, номером строки или порядком на экране. Карточки создаются из того же массива `tracks`; отдельного списка выдуманных неправильных ответов нет.

**Пример:** для 10 фрагментов существует ровно 10 уникальных карточек. Карточка «Моцарт — Симфония № 40» может быть неверной для фрагмента № 1 и правильной для фрагмента № 7. Неверная попытка в № 1 **не блокирует её для № 7**.

### 5.3. Режим «Тренировка» — поведение по умолчанию

1. Ученик слушает фрагмент и выбирает/перетаскивает карточку.
2. **Верный ответ:** зелёная подсветка, карточка закрепляется за фрагментом; этот фрагмент отмечается как изученный.
3. **Неверный ответ:** красная подсветка попытки; карточка возвращается в доступный набор (после короткой визуальной обратной связи), не закрепляется и может использоваться в другом вопросе.
4. Ошибаться и повторять попытки можно без ограничений; никакой штрафной оценки в режиме тренировки.
5. Можно переслушать исходный фрагмент и, при необходимости, отдельно прослушать произведение с ошибочно выбранной карточки для сравнения. В этом случае аудио карточки должно воспроизводиться из связанного с ней MP3.
6. Если все соответствия найдены, показать «Все произведения определены!» и предложить повторить тренировку или включить тест.

**Правило интерфейса:** в каждой области ответа не более одной *текущей* карточки. История ошибочных попыток может храниться отдельно, не заполняя экран дубликатами.

### 5.4. Режим «Тест» — два варианта для сравнения

Поведение теста **пока не утверждено окончательно**: необходимо реализовать оба варианта и выбрать после пробного использования с учениками.

**Вариант A — немедленная проверка:**

- После назначения карточки показывается зелёная или красная подсветка.
- Ошибочная карточка **может оставаться видимой у фрагмента красной**, как предложено в обсуждении.
- При этом она **остаётся доступной для других фрагментов**; визуальное размещение не означает исключительного владения карточкой.
- При новом ответе в той же области прежняя карточка заменяется; число попыток и ошибки можно учитывать.
- Правильные ответы отмечаются зелёным. Такой режим ближе к контролируемой тренировке; итог можно оценивать не только по конечному результату, но и по числу ошибок.

**Вариант Б — проверка в конце:**

- Назначение карточки не раскрывает правильность.
- До нажатия «Завершить тест» ответы нейтральны, их можно менять.
- После завершения подсвечиваются правильные и неправильные соответствия и показывается результат.
- Чтобы ошибочное назначение не лишало карточки другого фрагмента, **один ответ может временно назначаться нескольким фрагментам**. Это визуальные экземпляры одной карточки с одним ID, а не новые варианты ответа. После завершения каждое соответствие проверяется независимо.

**Общее правило для обоих вариантов:** неверное использование карточки не может сделать её недоступной там, где она правильна. Не реализовывать глобальную блокировку карточки просто по факту первого перетаскивания.

### 5.5. Что именно оценивается

Базовая единица проверки — **полное соответствие аудиофрагмента карточке**. Композитор, название и часть являются **полями одной карточки**, а не тремя отдельными вопросами. За совпадение ID — один правильный ответ; за несовпадение — неправильный. Итог для теста с отложенной проверкой: `правильных / всего × 100%`. Шкалу школьных оценок, штрафы за попытки и ограничения прослушиваний **не задавать без отдельного решения**.

При немедленной проверке сохранять число ошибок отдельно от количества окончательно верных соответствий: это разные показатели. Не считать неправильное размещение автоматической ошибкой во втором вопросе.

### 5.6. Состояние и взаимодействия

Рекомендуемая модель состояния в JavaScript:

- `quizId`, `mode` (`training` / `test`), `testFeedback` (`immediate` / `deferred`).
- `shuffledTrackIds`, `shuffledCardIds`.
- `assignments[trackId] = cardId | null` — текущие ответы.
- `lockedCorrectTrackIds` — закреплённые правильные ответы в тренировке.
- `attempts[trackId]` — история попыток/количество ошибок при немедленной проверке.
- `finished` — завершён ли тест.

Для режима с отложенной проверкой **не запрещать одинаковый `cardId` в разных `assignments`**. Для тренировки после ошибочной попытки не сохранять неверную карточку как закреплённую. При переключении режима предусмотреть явное подтверждение сброса текущего прохождения, чтобы случайное нажатие не меняло смысл уже полученных ответов.

## 6. Конструктор преподавателя (`teacher.html`)

**Учитель не редактирует код и не пишет JSON.** Это отдельная страница с обычными полями и кнопками. Она доступна в браузере без аккаунта для подготовки файла; публикация на GitHub — отдельное действие.

### 6.1. Верхняя часть: данные подборки

- Название викторины — обязательное поле.
- Класс/уровень — текстовое поле или выбор.
- Описание — необязательно.
- Кнопки **«Новая викторина»**, **«Открыть JSON»**, **«Сохранить JSON» / «Экспорт JSON»**.
- Удобный список добавленных произведений с возможностью изменения порядка.

### 6.2. Карточка произведения в редакторе

Для каждого элемента:

1. **Аудиофайл MP3:** выбрать из опубликованной библиотеки (по `data/mp3-index.json`) **или** выбрать локальный файл с компьютера.
2. Показать имя файла, возможность прослушать и состояние: «Уже загружен на сайт» / «Нужно загрузить в папку MP3».
3. **Композитор** — обязательное поле.
4. **Название произведения** — обязательное поле.
5. **Часть / номер / сцена** — необязательное поле.
6. Кнопки «Добавить произведение», «Удалить», «Переместить выше/ниже».

**Локальный выбор файла не загружает его на GitHub.** Браузер может проиграть выбранный файл и запомнить его **имя**, но не должен обещать, что файл уже опубликован. При повторном открытии черновика доступ к локальному файлу может потребоваться выбрать заново.

### 6.3. Умная обработка имён и повторного использования

- **Не переименовывать MP3 автоматически.** В JSON сохранять точное имя и относительный путь `MP3/<имя файла>`.
- При выборе уже опубликованного файла брать путь из индекса, без повторной загрузки.
- Если два разных локальных MP3 имеют одинаковое имя, предупреждать о конфликте: GitHub-папка не может хранить два разных файла с одним именем. Учитель должен выбрать существующий или осознанно переименовать новый **до экспорта**.
- Если разные викторины ссылаются на один MP3, это нормально.
- Если в одной викторине одинаковые композитор/название/часть встречаются несколько раз, предупредить о потенциально неразличимых карточках и предложить уточнить данные; не удалять молча.

### 6.4. Проверки перед экспортом

Проверять:

- Есть название подборки и хотя бы одно произведение.
- Для каждого произведения указаны композитор, название и MP3.
- Все `track.id` уникальны.
- Имена файлов и пути безопасны: только файлы внутри `MP3/`, без внешних URL и `../`.
- Нет повторяющихся ID подборок в доступном каталоге (если индекс удалось загрузить).
- Для файлов, отсутствующих в опубликованном MP3-индексе, выводить отдельный **список того, что нужно загрузить**.

Отсутствие нового MP3 на GitHub **не должно запрещать экспорт**: учитель может сначала скачать JSON, затем загрузить MP3. Но предупреждение должно быть ясным.

### 6.5. Импорт, экспорт и черновик

- **Импорт JSON:** проверить `schemaVersion`, показать понятные ошибки, заполнить форму для редактирования.
- **Экспорт JSON:** сформировать файл в формате UTF-8, скачать через браузер; имя файла — безопасный `id` подборки с расширением `.json`.
- **Автосохранение:** хранить незавершённый черновик локально в браузере (`localStorage` или `IndexedDB`), с восстановлением после перезагрузки. Не хранить там обещание о доступности локальных MP3.
- **Новая викторина:** спрашивать подтверждение, если текущий черновик не экспортирован.
- Показывать **предпросмотр** того, как будут выглядеть карточки ученика.

### 6.6. Обязательная инструкция внизу `teacher.html`

Разместить постоянно видимый блок «**Как опубликовать викторину**» простыми словами:

> **Шаг 1.** Создайте викторину и нажмите «Экспорт JSON». Файл сохранится на ваш компьютер.  
> **Шаг 2.** Откройте репозиторий DMSH_victorina на GitHub и папку **`MP3/`**. Если вы использовали новые MP3, загрузите их туда: **Add file → Upload files → Commit changes**. Уже имеющиеся записи повторно загружать не нужно.  
> **Шаг 3.** Откройте папку **`quizzes/`**. Загрузите туда скачанный файл `.json` тем же способом.  
> **Шаг 4.** Дождитесь обновления сайта, откройте главную страницу, выберите новую викторину и проверьте воспроизведение.  
> **Важно:** не меняйте имена MP3 после экспорта JSON. Если запись не звучит, проверьте имя и наличие файла в `MP3/`.

Сделать две явные ссылки-кнопки на соответствующие папки GitHub и, по возможности, отдельный блок «Какие MP3 ещё нужно загрузить». Указать, что загрузка файлов на GitHub требует прав на запись в репозиторий; **конструктором для создания JSON можно пользоваться без таких прав**.

## 7. Формат данных: JSON-схема версии 1

**Это целевой контракт между конструктором и страницами ученика.** Все части приложения должны использовать одну схему. При несовместимом `schemaVersion` показывать сообщение, а не угадывать структуру.

Пример **полного по структуре** файла с двумя произведениями (имена MP3 демонстрационные):

```json
{
  "schemaVersion": 1,
  "id": "nutcracker_3class",
  "title": "Балет «Щелкунчик»",
  "class": "3",
  "description": "Узнаём музыкальные номера балета",
  "tracks": [
    {
      "id": "track_001",
      "composer": "П. И. Чайковский",
      "work": "Балет «Щелкунчик»",
      "part": "Марш",
      "audio": "MP3/Tchaikovsky - March.mp3"
    },
    {
      "id": "track_002",
      "composer": "П. И. Чайковский",
      "work": "Балет «Щелкунчик»",
      "part": "Танец феи Драже",
      "audio": "MP3/Tchaikovsky - Sugar Plum Fairy.mp3"
    }
  ]
}
```

### Поля

| Поле | Тип | Обязательно | Значение |
|---|---|---|---|
| `schemaVersion` | число | да | Для первой версии строго `1` |
| `id` | строка | да | Уникальный постоянный ID подборки, безопасный для имени JSON |
| `title` | строка | да | Название, видимое ученику |
| `class` | строка | нет | Класс/уровень, например `3` |
| `description` | строка | нет | Краткое описание |
| `tracks` | массив | да | Непустой список произведений |
| `tracks[].id` | строка | да | Уникальный ID внутри подборки |
| `tracks[].composer` | строка | да | Композитор |
| `tracks[].work` | строка | да | Название произведения |
| `tracks[].part` | строка | нет | Часть, действие, номер или пустая строка |
| `tracks[].audio` | строка | да | Путь вида `MP3/имя.mp3` от корня сайта |

**Важно:** `track.id` не обязан совпадать с именем MP3; изменение названия карточки не должно ломать соответствие. Для новой подборки конструктор создаёт уникальный `id`; при импорте существующей сохраняет прежние ID, пока преподаватель явно не создаст копию как новую подборку.

### Каталог викторин: `quizzes/index.json`

Пример:

```json
{
  "schemaVersion": 1,
  "quizzes": [
    {
      "id": "nutcracker_3class",
      "file": "quizzes/nutcracker_3class.json",
      "title": "Балет «Щелкунчик»",
      "class": "3",
      "description": "Узнаём музыкальные номера балета",
      "trackCount": 2
    }
  ]
}
```

Индекс должен генерироваться автоматически из валидных файлов `quizzes/*.json`, **кроме самого `index.json`**. Невалидный файл не должен ломать каталог остальных викторин: сборка выводит диагностическое сообщение о конкретном файле. Идентификаторы должны быть уникальными; конфликт — ошибка публикации.

### Индекс MP3: `data/mp3-index.json`

Пример:

```json
{
  "schemaVersion": 1,
  "files": [
    "MP3/Tchaikovsky - March.mp3",
    "MP3/Tchaikovsky - Sugar Plum Fairy.mp3"
  ]
}
```

Индекс строится сканированием `MP3/`, включая при необходимости вложенные папки (для первой версии допустима только одна папка без вложений — это надо последовательно соблюдать в конструкторе и генераторе). В индекс включаются только поддерживаемые аудиофайлы; первая версия ориентируется на **MP3**.

## 8. Публикация и обновление на GitHub

**Один раз при разработке:** настроить GitHub Pages, GitHub Actions, права workflow и создание двух индексов. **После этого преподаватель только загружает файлы.**

Рекомендуемый порядок автоматизации:

1. При `push` с изменениями в `quizzes/*.json` или `MP3/**` запускается workflow.
2. Скрипт проверяет JSON, наличие обязательных полей и допустимость путей.
3. Формирует `quizzes/index.json` и `data/mp3-index.json`.
4. Публикует обновлённый статический сайт через GitHub Pages (предпочтительно сборка артефакта Pages, без коммита генерируемых индексов обратно в ветку). Так не возникает рекурсивных коммитов.
5. При ошибке сообщает имя проблемного JSON в журнале Actions.

**Не предполагать, что GitHub Pages сам автоматически обновляет индекс файлов.** Это задача workflow.

### Что делать при 2, 10 или 100 викторинах

Ничего не удалять. В `quizzes/` лежат разные JSON, все они ссылаются на общий набор `MP3/`. Одна запись может участвовать в нескольких викторинах. Для изменения существующей подборки преподаватель открывает её JSON в конструкторе, редактирует и экспортирует с тем же ID/именем, затем заменяет файл в GitHub. Для создания **новой** подборки — новый ID и новый JSON. Удаление MP3 допустимо только после проверки, что на него больше не ссылается ни одна опубликованная викторина.

### Публичность и авторские права

Если репозиторий и GitHub Pages публичны, MP3 также фактически доступны всем. Перед публикацией проверять права **на конкретные записи**, даже если произведения композиторов находятся в общественном достоянии. Для материалов, которые нельзя публиковать, понадобится другая схема хранения/доступа.

## 9. Совместимость, удобство и устойчивость

- **Платформы:** macOS, Windows, Linux, Android, iOS/iPadOS через браузер.
- **Школьные компьютеры:** Intel iMac с macOS High Sierra; проверить работу на реально установленной доступной версии браузера. Не использовать без полифиллов API, отсутствующие в целевых браузерах.
- **Адаптивность:** большой экран, планшет, телефон. Для мобильного управления — выбор касаниями как обязательный альтернативный способ.
- **Доступность:** крупные области нажатия, видимый фокус клавиатуры, текстовые подписи цветов («Верно»/«Ошибка»), управление без точного drag-and-drop.
- **Звук:** один активный MP3; обработка паузы, конца записи и ошибки загрузки; не полагаться на autoplay.
- **Скорость:** не скачивать все MP3 всех викторин при открытии главной; загружать только необходимое.
- **Безопасность:** пользовательские строки вставлять как текст, а не как HTML; проверять JSON; не хранить GitHub-токены в коде сайта.
- **Автосохранение черновика:** локально на устройстве учителя; явно сообщать, что очистка данных браузера может удалить черновик.
- **Офлайн/PWA:** желательное развитие после первой версии. Офлайн-доступ требует явного скачивания выбранной подборки и её MP3, а не только установки иконки PWA.
- **Результаты учеников:** в первой версии могут показываться на экране без сервера. Учётные записи, синхронизация и журнал преподавателя — отдельный этап, не выдавать за реализованные функции.

## 11. Приёмочные сценарии: что обязательно проверить

1. **Две викторины:** добавить `quiz_A.json` и `quiz_B.json` с общим MP3 → обе видны в каталоге, звук работает, HTML не менялся.
2. **Ошибка без потери ответа:** карточка B ошибочно выбрана для фрагмента A → B остаётся доступной для фрагмента B; можно правильно ответить на оба задания.
3. **Независимая проверка:** в отложенном тесте одна карточка назначена двум фрагментам → приложение не блокирует второе назначение; при завершении проверяет каждый фрагмент по ID.
4. **Изучение:** ученик запускает одну запись, затем другую → первая останавливается; названия всегда видны.
5. **Новый MP3:** преподаватель выбирает локальный файл, экспортирует JSON → редактор предупреждает, что MP3 нужно отдельно загрузить в `MP3/`.
6. **Импорт и исправление:** экспортировать JSON, импортировать обратно, изменить название части, снова экспортировать → данные сохранены корректно.
7. **Новый набор без программирования:** учитель добавляет JSON в `quizzes/`, при необходимости MP3 в `MP3/` → после публикации набор появляется на главной без правки страниц.
8. **Кириллица и пробелы:** MP3 с пробелами и русскими буквами в имени корректно воспроизводится.
9. **Плохой JSON:** ошибочная подборка выдаёт понятную диагностику, другие подборки остаются доступными.
10. **Телефон:** все ответы можно назначить касаниями, не используя drag-and-drop.

## 12. Вопросы, оставленные на испытание прототипа

Эти решения **не следует выдавать за окончательно согласованные**:

- В режиме «Тест» удобнее **немедленная подсветка** или **проверка после завершения**? Реализовать оба варианта и сравнить с детьми.
- Нужно ли в тесте с немедленной проверкой закреплять верные ответы или разрешать свободно менять любые назначения? На первом этапе допустим вариант с зелёным закреплением, но поведение проверить на практике.
- Какую школьную оценку ставить за процент правильных ответов и нужно ли учитывать число попыток? Пока показывать объективные показатели без произвольной шкалы.
- Нужен ли обязательный минимум прослушиваний перед переходом к викторине? Пока **нет**: обучение свободное.
